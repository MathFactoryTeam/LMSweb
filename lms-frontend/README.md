# 여정의 아카이브 프론트엔드

여정의 아카이브 백엔드(`lms-backend`)에 붙는 Next.js 화면입니다. Vercel 배포를 기준으로 만들었습니다.

## 실행

```bash
npm install
npm run dev:mock        # 백엔드 없이 가짜 데이터로 실행 (학생 student1, 선생님 teacher1, 비밀번호 아무거나)
npm run dev             # 실제 백엔드에 연결 (.env.local 에 NEXT_PUBLIC_API_BASE_URL 설정)
npm run build           # 배포용 빌드
```

목업 모드 데이터는 메모리에만 있어서 새로고침하면 처음 상태로 돌아갑니다.

## 화면

| 경로 | 학생 | 선생님 |
|---|---|---|
| `/login`, `/signup` | 로그인, 가입 요청 (아이디, 비밀번호, 반, 이름, 휴대폰 번호) | 로그인 |
| `/` | 마감 전 숙제와 내 제출 상태, 안 읽은 알림 | 내 반, 가입 승인 대기, 최근 알림 |
| `/classrooms` | 내 반 목록 | 반 만들기, 반 삭제 |
| `/classrooms/[id]` | 숙제 목록, 내 질문, 질문하기 | 숙제 내기, 숙제 목록, 학생 질문, 학생 목록(누르면 학생 화면), 학생 추가 |
| `/students/[id]` | 들어갈 수 없음 (서버가 403) | 학생 정보, 선생님 메모 (부모님 전화번호, 기타 사항) |
| `/me` | 내 정보: 휴대폰 번호, 비밀번호 바꾸기 | 같음 |
| `/homeworks/[id]` | 사진 제출, 내 사진, 피드백 | 학생별 제출 현황 |
| `/submissions/[id]` | 숙제 화면으로 이동 | 사진 보기, 피드백과 점수 |
| `/questions/[id]` | 질문과 답변 | 답변 달기 |
| `/signup-requests` | 없음 | 가입 승인, 거절, 보호자 동의 확인 |
| `/notifications` | 알림 (누르면 해당 화면으로) | 알림 |
| `/chat` | AI 질문 (스트리밍, 하루 남은 횟수) | 없음 |

## 구조

```
src/
├── app/
│   ├── login, signup          로그인 전 화면
│   └── (app)/                 로그인 후 화면 (공통 메뉴와 세션 확인)
├── components/
│   ├── AppShell.tsx           PC 왼쪽 메뉴, 휴대폰 아래쪽 탭
│   ├── PhotoUploader.tsx      사진 고르기 → 업로드 URL → S3 직접 업로드 → 제출 완료
│   ├── PhotoGrid.tsx          제출 사진 보기
│   └── ui.tsx                 버튼, 입력칸, 상태 배지, 남은 시간 표시
└── lib/
    ├── api.ts                 API 호출 (쿠키, 429/503 재시도, 챗봇 스트림)
    ├── session.tsx            /api/dashboard 한 번으로 로그인 확인과 메인 화면 데이터
    ├── mock.ts                목업 모드 가짜 API
    └── types.ts               백엔드 응답 타입
```

## 마감 시간 부하를 위해 프론트에서 지키는 것

- 로그인 확인, 메뉴의 알림 숫자, 학생 홈 화면을 모두 `/api/dashboard` 한 번으로 그립니다. 학생이 홈에서 새로고침하면 요청은 1건입니다.
- 429, 503을 받으면 `Retry-After` 만큼 기다리고, 0~0.8초를 무작위로 더 기다린 뒤 다시 부릅니다. 500명이 같은 순간에 다시 몰리지 않게 하기 위해서입니다. 다시 보내도 안전한 GET만 재시도합니다.
- 2MB가 넘는 사진은 올리기 전에 긴 변 2,200px JPEG로 줄입니다. HEIC는 브라우저가 그리지 못하는 경우가 많아 그대로 올립니다.
- 사진은 Spring 서버를 거치지 않고 S3로 바로 올라갑니다.
- 숫자 갱신은 화면이 보일 때만 1분마다 합니다.

## 배포 (Vercel)

1. 저장소를 Vercel에 연결하고 환경 변수 `NEXT_PUBLIC_API_BASE_URL` 을 설정합니다.
2. 프론트는 `app.도메인`, 백엔드는 `api.도메인` 처럼 같은 상위 도메인을 써야 로그인 쿠키가 함께 갑니다.
3. 백엔드 `CORS_ALLOWED_ORIGINS` 에 프론트 주소를 넣습니다.

## 아직 남은 것

- 백엔드에 반 하나를 조회하는 API가 없어서, 반 화면은 `/api/classrooms` 목록에서 찾아 이름을 보여 줍니다.
- 실제 백엔드와 붙여서 확인하지는 않았습니다. 목업 모드로 화면과 흐름만 확인했습니다.
- 휴대폰 홈 화면 추가(PWA)와 다크 모드는 넣지 않았습니다.
